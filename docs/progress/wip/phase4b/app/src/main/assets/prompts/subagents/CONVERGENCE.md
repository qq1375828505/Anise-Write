# 子代理收敛协议（CONVERGENCE）

> 适用范围：PenAi 6 个创作子代理（outline / character / foreshadow / polish /
> review / consistency）的结果汇总、冲突判定与收敛迭代。
> 上位依据：规划书 §5.3（主代理收敛 + 去重 + 优先级裁决）、§6.6（职责边界矩阵、
> 冲突仲裁规则、3 轮迭代收敛）。
> 本协议是主 AI（编排者）的行为规则，不是子代理的提示词。

## 0. 总原则

1. **子代理零写权限**。全部子代理只读 + 产出建议态；落库、改稿、改状态只能由
   主 AI 经 `novel_*` 写工具执行。子代理输出一律是主 AI 的决策输入。
2. **主 AI 是唯一编排者**。派发、汇总、裁决、落库四件事全部收在主 AI 一处；
   子代理之间不发生直接调用。
3. **冲突不私了**。子代理之间、子代理与权威源之间的冲突，一律按本协议显式处理，
   禁止主 AI 静默挑选一个当结论。

## 1. 权威源规则

同一事实存在多个来源时，按以下优先级判定谁是权威源（越靠前越权威）：

| 优先级 | 权威源 | 覆盖范围 | 数据位置 |
|---|---|---|---|
| P0 | 用户明示要求 | 一切（见 §2） | 会话原文 |
| P1 | 已定稿章节正文 | 情节事实、人物已发生的行为、事件顺序 | `filesDir/novel/chapters/` |
| P2 | 资料库（8 类资料卡） | 角色属性、世界观规则、道具、势力设定 | `filesDir/novel/materials/` |
| P3 | 伏笔台账 | 伏笔埋/收/废弃状态、闲置章数 | `novel_hooks_status` 域 |
| P3 | 关系图三表 | 关系类型、强度 1-5 | 关系/事件/参与者表 |
| P4 | 大纲/细纲 | 计划态结构（卷/章/节） | `filesDir/novel/outline/` |

规则要点：

- **伏笔状态冲突，台账是唯一权威源**。foreshadow 代理的审计意见
  （如「台账记已回收但正文无迹象」）只能作为 `authority_conflict` 上报，
  由主 AI 附证据转用户确认后，才由主 AI 改台账。
- **关系数据冲突，三表是唯一权威源**。character 代理推导的关系边是建议态，
  与三表互斥时以上报处理，不直接覆盖。
- **正文 vs 资料卡**：默认资料卡为权威源（P2 > 计划态）；但若冲突发生在
  两处已定稿章节之间，双方同级，属 `unclear`，交用户裁决。
- **细纲 vs 正文**：正文偏离细纲不是错误，记「漂移」进 `drift_notes`，
  不报冲突；只有漂移导致后续细纲不可执行时才上报。

## 2. 优先级裁决链

建议冲突时按以下顺序裁决，取第一个能给出结论的层级：

1. **用户明示要求**（`constraints.user_requirements`）：最高优先级，
   任何默认规则不得覆盖；执行了与默认规则相悖的用户要求时，必须在汇总里注明。
2. **权威源**：与 P1-P4 中更权威来源一致的一方胜出。
3. **领域特化**：同优先级来源之间，领域代理的意见优先于通用意见——
   伏笔问题以 foreshadow 为准，精修问题以 polish 为准，人设/关系问题以
   character 为准，逻辑/人设崩塌/节奏以 review 为准，数据级比对以
   consistency 为准。越界发表的意见（如 polish 评价情节逻辑）权重最低。
4. **证据强度**：仍不能分胜败时，比证据——能引用具体章号/段落/字段定位的
   一方胜出；都引用或都不引用，比 `confidence`；仍持平 → 升级用户。
5. **升级**：写入 `escalations`（`user_decision`），双方证据并列呈现，
   主 AI 不下结论。

## 3. 冲突分类与处理流程

| 冲突类 | 定义 | 处理 |
|---|---|---|
| 事实冲突 | 两个子代理对同一对象给出互斥断言（如 A 说角色已死、B 说角色在世） | 走 §2 裁决链；链尾仍悬置 → 升级用户 |
| 建议冲突 | 修改建议互斥（如 polish 建议删段、outline 建议该段承载伏笔） | 按 §2 层级 3-4 裁；无法裁 → 合并为「两个方案+后果」交用户 |
| 定级冲突 | 同一问题严重度判定不同（review 定 blocker、consistency 定 suggestion） | 取高定级，保守处理；在汇总注明定级分歧 |
| 与权威源冲突 | 子代理意见与 P1-P4 数据互斥 | 不改数据，附证据升级用户；用户拍板后由主 AI 执行变更 |

处理流程（主 AI 每轮汇总时执行）：

1. 收集本轮全部子代理输出。
2. 按「对象 + 位置/范围」聚类（见 §4 去重）。
3. 逐聚类判冲突类，走对应处理。
4. 输出汇总：结论 + 依据 + 待用户裁决清单 + 已执行/待执行动作清单。

## 4. 去重规则

多代理结果合并时，按以下键去重：

- 审查类问题（review / consistency / foreshadow）：
  键 =（类型, 对象, 定位）。定位精确到「章号+段落」或「资料卡+字段」；
  键相同的条目合并为一条，保留证据更全、定级更高的一条，
  `evidence` 取并集。
- 建议类条目（polish / outline / character）：
  键 =（目标对象, 修改内容哈希）。内容相同取高 `confidence`；
  内容互补（改的是同一段落的不同维度）保留多条，标注可叠加。
- 同源上报：两个代理引用同一章节证据说明同一问题时，只保留一次证据。

## 5. 收敛迭代规则

- **轮数上限 3 轮**。第 2 轮起，主 AI 派发时必须在信封 `previous_round`
  携带上轮输出，子代理提示词要求「检查并优化上一轮结果」——在旧址上改，
  不允许推倒重来。
- **提前收敛判据**：第 2 轮与第 1 轮输出长度差 < 5%（按字符数）判定收敛，
  停止后续轮次。长度差 ≥ 5% 时进入第 3 轮；第 3 轮后无论是否收敛都停止，
  以最后一轮为准并注明未完全收敛。
- **收敛失败处理**：3 轮后仍有 `blocker` 级未解决问题 → 不进入自动重试，
  汇总为「待用户决策清单」上交。
- **子代理执行失败**（`status=error` 或输出不可解析）：主 AI 返回可用
  子代理清单与失败原因引导重派；同一委派重试不超过 1 次，仍失败则跳过该
  代理并在汇总注明缺口。

## 6. 升级路径

| 情况 | 升级对象 | 形式 |
|---|---|---|
| 与权威源冲突、双方都是定稿正文 | 用户 | 双方证据并列 + 主 AI 的倾向性判断（明确标注为倾向） |
| 建议冲突且后果不可逆（删伏笔、改人设锚点） | 用户 | 两方案 + 各自后果 |
| 输入不足且无法自动补取 | 用户 | 缺什么、要用户提供什么 |
| 3 轮未收敛 | 用户 | 未收敛点清单 + 当前最优解 |

升级时主 AI 必须给出：冲突双方原文证据、本协议适用条款、自己的倾向性判断
（有法可依才给，没有就明说无法判断）。
