## 5. 事故清单（今天踩的坑，务必记住）

1. **作用域**：跨组合函数用状态必须**逐层传参**，不能闭包捕获上层局部变量（`showNovelStudio` 教训）。
2. **Canvas 绘制层不能读 `@Composable` 状态**：先在外部取值再进 `Canvas {}`。
3. **GitHub API 创建 commit**：更新 ref 必须用**完整 40 位 sha**（短 sha → 422）；未挂 ref 的 commit 对象 GET 会 404。
4. **Git Data API 会归一化 commit**（时间→`+0000`、去掉消息末尾换行）→ 远端 sha 与本地必不同但**树一致**；
   收尾：`git fetch` → `git rebase origin/feature/penai`（会提示 "skipped previously applied commit"）→ 正常快进 push，**无需 force**。
5. **沙箱网络**：`github.com:443` 时断时续（DNS 通、TCP 连不上），`api.github.com` 通常可达；
   连不上时走 Git Data API 也能推上去。
6. **挂载会瞬时丢文件**：`/var/minis/mounts/Ai` 曾"丢失" 8 个二进制资源（头像/mipmap/ts 模板）→ `git checkout --` 即恢复。
   遇到疑似误删先查挂载，别急着怀疑代码。
7. **gitdir 指针三处同步**：挂载区 `.git` 指针文件 + gitdir `config` 的 `core.worktree` + 脚本里的绝对路径，漏一处就 "not a git repository"。
8. **`rg` 不要用 `-r`**（那是替换不是递归）；大文件 `file_write` 要拆段（≤8KB），否则流式卡死。
9. **CI 并发取消**：`.github/workflows/build.yml` 有 `cancel-in-progress: true` → 同一分支再推一次会把在跑的 run 取消掉
   （cancelled ≠ 失败）。

## 6. 模型组 / 写作档（方案已定，待做）

**调查结论**：Minis 的模型组**不是 UI 分组，是路由策略层**（成员有序 + `fallback`/`loadBalance` 策略 +
`fallbackStrategy` + 组级上下文上限/思考档）；子代理可**钉住**一组，未钉住时委派模型只能表达
**三选一的意图**（`same_as_me` / `default_model` / `sub_model`）——因为"哪个模型强/便宜"是用户的知识，
"任务多难"才是模型的知识。Minis 自己在注释里废掉过让模型自选档位的旧机制。

**我们的现状**：基座已有 `QuroMultiProviderRepository`（多 provider + 优先级 + 健康）与
`QuroFailoverManager`（provider 级故障转移）→ **不重复造**；缺的是命名模型组、默认/轻量组、子代理绑组。
且**6 个写作子代理 + 全部 novel 工具共用一个模型**（`callLlm` 写死 `cfg.model`）——这才是真痛点。

**决策**（用户）：全套做；入口 = **设置里的独立条目「模型组」**（不挂模型配置子页、不进工作台页签）。

**进度**：数据模型 + 仓储 + 路由 + 委派工具接入已写（WIP `0835675`）；
UI、`DELEGATION.md` schema、预置引导、真机验证待做。详见 `docs/design/ModelGroup_SPEC.md`。
